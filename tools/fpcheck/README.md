# 計算機による浮動小数点の違いの調べ（Intel i7・i9 と Apple M5 Max・M6）

状態：**下調べ**。4 台の実機ではまだ測っていない。ここにある数値は、クラウドの x86 の計算機（Intel Xeon）と、その上の ARM64 のエミュレーター（QEMU）で測ったもの。実機の値は「実機での測り方」の手順で取る。

## 1. 結論（この調べで言えること）

| 問い | 答え | 裏づけ |
|---|---|---|
| CPU の演算そのもの（＋ − × ÷ √）は Intel と Apple で違うか | **違わない。** 1 ビットも違わなかった | 測った（表 1 の A） |
| では、同じプログラムの結果は同じになるか | **コンパイルのしかたで変わる。** ARM64 向けのコンパイラは既定で a×b+c を 1 回の丸めにまとめる（FMA）。x86 の既定ではまとめない。この違いで式 1 つあたり最後の 1〜数桁（相対 10⁻¹⁶ の程度）が変わる | 測った（表 1 の C・D） |

| M5 Max と M6 のあいだ | 同上（どちらも ARM64 で、演算の決まりは同じ） | 推測（実機で未確認） |

**報告書の計算への当てはめ**（推測。OpenFOAM で確かめてから書くこと）

- 「判定を満たして停止」した定常の計算：計算機を替えたときの差は、反復の誤差（止め方の判定値）より小さい見込み。格子の誤差（数 %〜数十 %）よりはるかに小さい。
- 「極限周期」「打ち切り」の計算と、非定常の計算の瞬時の値：計算機を替えると、位相による振れの幅まで違いうる。これは丸めの誤差が大きいからではなく、落ち着かない計算が小さな違いを育てるため。報告書がすでに書いている「位相による振れ」と同じ大きさで読めばよい。
- **計算機の違いより大きいもの**：並列数（領域の分け方）を変えると、和の順番と線形ソルバーの前処理が変わり、同じ計算機でも結果が変わる。コンパイルのしかた（FMA、`-ffast-math`）とライブラリの版も同じ。計算機を比べるときは、この 3 つをそろえる。

## 2. なぜ違いが出るか

倍精度の数は有効数字が約 16 桁で、演算のたびに最後の桁を丸める。IEEE 754 は、四則と平方根の結果を「正しい値にいちばん近い数」と決めているので、決まりを守る CPU ならどれでも同じ結果になる。Intel（SSE2・AVX）も Apple シリコン（ARM64）もこれを守っている。違いが出るのは、CPU ではなく次の所である。

1. **a×b+c のまとめ（FMA）**：FMA は a×b を丸めずに c を足し、最後に 1 回だけ丸める。別々に計算すると 2 回丸める。ARM64 は FMA を必ず持つので、GCC は既定でまとめる。x86-64 は基準の命令に FMA が無いので、`-march=native` などを付けないとまとめない。
2. **数学関数のライブラリ**：exp・log・sin などは IEEE 754 で「正しく丸める」ことを求められていない。ライブラリ（glibc、Apple の libm、Intel の libm）と版で最後の桁が変わる。glibc は実行時に CPU を見て、FMA を使う版と使わない版を選ぶ。
3. **和の順番**：浮動小数点の足し算は順番で結果が変わる。並列数を変える、`-ffast-math` でベクトル化を許す、BLAS などのライブラリが CPU に合わせて計算の道を選ぶ、で順番が変わる。
4. **long double**：x86-64 の Linux は 80 ビット、ARM64 の Linux は 128 ビット、Apple シリコンの macOS は 64 ビット（double と同じ）。OpenFOAM の倍精度（既定）の計算は double を使うので、ふつうは効かない。

P コアと E コア（i7-1255U は P 2 + E 8）は同じ命令を同じ決まりで実行するので、どのコアで走っても結果は同じ。

## 3. 測ったこと

`fpcheck.c` を 8 通りに作り、同じ入力に対する結果を 1 ビット単位で比べた。計算機は Intel Xeon（AVX2・FMA・AVX-512 あり）、Ubuntu 24.04、GCC 13.3、Clang 18.1、glibc 2.39。ARM64 は同じ GCC の ARM64 向けで作り、QEMU で走らせた。

表 1　基準（x86、`gcc -O2 -ffp-contract=off`）と違った項目。ULP は「倍精度で隣り合う数」いくつ分か

| | 比べた相手 | 四則・√ | 数学関数 | 打ち消しのある式 a×b−c×d | 内積・和 | 収束する反復（ラプラス） | カオス（ローレンツ） |
|---|---|---|---|---|---|---|---|
| A | x86、既定（`gcc -O2`） | 同じ | 同じ | 同じ | 同じ | 同じ | 同じ |
| B | x86、同じ実行ファイルを FMA の無い CPU として走らせる | 同じ | exp・pow・sin・cos・atan2 の 10〜23 点 / 2 万点が 1 ULP | 同じ | 同じ | 同じ | 同じ |
| C | x86、`-march=native`（FMA を使う） | 同じ | 同じ | 36 % の点が違う。差は最大 1.1×10⁻¹³（値は 10³ まで） | 同じ | 同じ | 違う（表 2） |
| D | ARM64、既定（FMA を使う） | 同じ | cbrt だけ 20 % の点が違う、最大 4 ULP | C と同じ | 同じ | 同じ | 違う（表 2）。**C とは 1 ビットも違わない** |
| E | ARM64、`-ffp-contract=off` | 同じ | cbrt だけ（D と同じ） | 同じ | 同じ | 同じ | 同じ |
| F | x86、`-O3 -march=native -ffast-math` | 同じ | 8 つの関数すべて、23〜68 % の点が 1〜3 ULP | C と同じ | 34 ULP（相対 6×10⁻¹⁵） | 56 % の点が違う。差は最大 4×10⁻¹⁶（値は 1 まで）。反復の数は同じ 5,219 | 違う |

読み方：

- A・E：FMA を止めれば、x86 と ARM64 は cbrt を除いてすべて同じ。**CPU の演算に違いは無い。**
- C と D が同じ：ARM64 の既定と、x86 で FMA を使った場合は、cbrt を除いて 1 ビットも違わない。**違いを作っているのは CPU の種類ではなく、FMA を使うかどうか。**
- 収束する反復：F を除いて全点が同じ。ただしこのラプラス方程式の反復は 0.25 倍（丸めの出ない掛け算）と足し算だけで、FMA の効く式が無い。積の入る式での確かめは OpenFOAM の計算で行う（4 章）。

## 4. 実機での測り方

### 4.1 fpcheck（各計算機で 1 分）

各計算機（i7・i9・M5 Max・M6）で次を実行し、できた `.txt` と `.bin` を 1 か所に集める。

```bash
cc -O2 -o fpcheck fpcheck.c -lm
```

```bash
./fpcheck "$(hostname).bin" > "$(hostname).txt"
```

集めた所で 2 台ずつ比べる。

```bash
python3 compare.py i7.bin m6.bin
```

`.txt` の先頭に、その計算機のコンパイラ、FMA にまとめたか、long double のビット数が出る。OpenFOAM を Docker の中で走らせている計算機では、fpcheck も同じ Docker の中で作って走らせる（数学関数のライブラリが macOS のものと違うため）。

### 4.2 OpenFOAM の計算（報告書に載せるならこちらが要る）

fpcheck は小さな式の違いを見るもので、報告書の量（風速比、流量、温度）がどれだけ違うかは OpenFOAM の同じケースを各計算機で走らせて比べる。そろえるもの：

1. OpenFOAM の版と作り方（同じ版。Docker なら同じイメージの x86 版と ARM64 版）
2. 並列数と領域の分け方（まず 1 並列。次に同じ並列数・同じ `decomposeParDict`。`scotch` は版で分け方が変わるので `simple` か `hierarchical`）
3. 出力の桁（`writePrecision 16` か `writeFormat binary`）
4. 反復の数（判定で止めず、同じ反復の数で止める）

選ぶケース：(a) 判定を満たして停止した定常の計算 1 本、(b) 極限周期か打ち切りの計算 1 本。(a) で報告する量の差が反復の誤差より小さいこと、(b) で差が位相による振れの幅に入ることを見る。結果を見る前に、見立て（例：(a) は報告する量で相対 10⁻⁶ 以下）を書いておく。

## 5. まだ確かめていないこと

- 4 台の実機での測定（この文書の数値はクラウドの x86 とエミュレーター）
- Apple の libm（macOS でじかに作った場合）と glibc の違いの大きさ
- OpenFOAM の計算での違いの大きさ（4.2 節）
- 使っている OpenFOAM がどのコンパイラ・どの設定で作られているか（FMA にまとめているか）
- M6 の仕様（ARM64 であることを前提にした）
