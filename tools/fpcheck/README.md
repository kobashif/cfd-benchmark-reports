# 計算機による浮動小数点の違いの調べ（Intel i7・i9 と Apple M5 Max・M6）

状態：**下調べ**。4 台の実機ではまだ測っていない。ここにある数値は、クラウドの x86 の計算機（Intel Xeon）と、その上の ARM64 のエミュレーター（QEMU）で測ったもの。実機の値は「実機での測り方」の手順で取る。

## 1. 結論（OpenFOAM の計算で言えること）

同じ OpenFOAM の版・同じケース・同じ並列数（1 並列）を、x86 と ARM64 で走らせて比べた（3.3 節）。

1. **結果は 1 ビット単位では一致しない。** 最初の反復で 15 桁目に出た違いが、2 回目の反復で圧力の線形ソルバーの反復の数を 1 回ずらし（14 回と 15 回）、そこから差が線形ソルバーの止め方（相対の判定 0.1）の大きさまで一気に広がる。丸めの誤差そのもの（10⁻¹⁶）ではなく、**反復の止め方が差の大きさを決める。**
2. **差は反復が進むと縮み、反復の誤差より小さい。** 判定を満たして停止した解（x86・ARM64 とも 280 反復で停止）で、速度の差は最大で入口の速度の 0.06 %。同じ解と 1,500 反復まで回した解との差（反復の誤差）は 0.8 % で、計算機の差はその 14 分の 1。
3. **並列数を変えたときの差のほうが大きい。** 同じ x86 で 1 並列と 2・4 並列を比べると、250 反復で速度の差は 0.14〜0.21 %。x86 と ARM64 の差（0.04 %）の 3〜5 倍。
4. **長く回しても差は 0 にならない。** 500 反復から先は残差が下げ止まり、x86 と ARM64 の速度の差は最大 0.02〜0.05 % のまま。同じ計算機の 1,000 反復と 1,500 反復の差（0.02 %）と同じ大きさで、解そのものの揺れの中にある。

**無視できるか**：格子の誤差（報告書では数 %〜数十 %）や測定との差に比べれば、無視できる。ただし「計算機を替えても同じ数字が出る」とは言えず、**有効数字 3 桁までは同じ、4 桁目から変わりうる**と読むのが実測に合う。報告書の量を 3 桁で書くかぎり、計算機の違いは表に出ない見込み（このケースでの値。報告書のケースでは未確認）。

落ち着かない計算（極限周期・打ち切り・非定常の瞬時の値）は OpenFOAM では測っていない。小さな式の実験（3.2 節）では、瞬時の値は振れ幅いっぱいまで違い、時間平均は 0.2 % で一致した。報告書の「位相による振れ」と同じ大きさで違いうると読む（推測）。

i7 と i9、M5 Max と M6 のあいだは、同じ実行ファイル・同じライブラリ・同じ並列数なら同じ結果になる見込み（推測、実機で未確認）。P コアと E コアは同じ命令を同じ決まりで実行するので、どのコアで走っても結果は同じ。

**この調べの限界**

- OpenFOAM は Ubuntu 24.04 のパッケージの v1912（報告書の計算は v2606）。x86 版は FMA を使わず、ARM64 版は FMA を使う作り（実行ファイルを調べた）
- ARM64 は Apple の実機ではなく QEMU のエミュレーター。演算の結果は IEEE 754 のとおりで実機と同じはずだが、確かめていない。数学関数は glibc で、macOS でじかに作った場合の Apple のライブラリとは違う
- ケースは 1 つ（pitzDaily、2 次元、12,225 セル、simpleFoam、k-ε）

## 2. なぜ違いが出るか

倍精度の数は有効数字が約 16 桁で、演算のたびに最後の桁を丸める。IEEE 754 は、四則と平方根の結果を「正しい値にいちばん近い数」と決めているので、決まりを守る CPU ならどれでも同じ結果になる。Intel（SSE2・AVX）も Apple シリコン（ARM64）もこれを守っている。違いが出るのは、CPU ではなく次の所である。

1. **a×b+c のまとめ（FMA）**：FMA は a×b を丸めずに c を足し、最後に 1 回だけ丸める。別々に計算すると 2 回丸める。ARM64 は FMA を必ず持つので、GCC は既定でまとめる。x86-64 は基準の命令に FMA が無いので、`-march=native` などを付けないとまとめない。
2. **数学関数のライブラリ**：exp・log・sin などは IEEE 754 で「正しく丸める」ことを求められていない。ライブラリ（glibc、Apple の libm、Intel の libm）と版で最後の桁が変わる。glibc は実行時に CPU を見て、FMA を使う版と使わない版を選ぶ。
3. **和の順番**：浮動小数点の足し算は順番で結果が変わる。並列数を変える、`-ffast-math` でベクトル化を許す、BLAS などのライブラリが CPU に合わせて計算の道を選ぶ、で順番が変わる。
4. **long double**：x86-64 の Linux は 80 ビット、ARM64 の Linux は 128 ビット、Apple シリコンの macOS は 64 ビット（double と同じ）。OpenFOAM の倍精度（既定）の計算は double を使うので、ふつうは効かない。

P コアと E コア（i7-1255U は P 2 + E 8）は同じ命令を同じ決まりで実行するので、どのコアで走っても結果は同じ。

## 3. 測ったこと

### 3.1 小さな式（fpcheck）

`fpcheck.c` を 8 通りに作り、同じ入力に対する結果を 1 ビット単位で比べた。計算機は Intel Xeon（AVX2・FMA・AVX-512 あり）、Ubuntu 24.04、GCC 13.3、Clang 18.1、glibc 2.39。ARM64 は同じ GCC の ARM64 向けで作り、QEMU で走らせた。

表 1　基準（x86、`gcc -O2 -ffp-contract=off`）と違った項目。ULP は「倍精度で隣り合う数」いくつ分か

| | 比べた相手 | 四則・√ | 数学関数 | 打ち消しのある式 a×b−c×d | 内積・和 | 収束する反復（ラプラス） | カオス（ローレンツ） |
|---|---|---|---|---|---|---|---|
| A | x86、既定（`gcc -O2`） | 同じ | 同じ | 同じ | 同じ | 同じ | 同じ |
| B | x86、同じ実行ファイルを FMA の無い CPU として走らせる | 同じ | exp・pow・sin・cos・atan2 の 10〜23 点 / 2 万点が 1 ULP | 同じ | 同じ | 同じ | 同じ |
| C | x86、`-march=native`（FMA を使う） | 同じ | 同じ | 36 % の点が違う。差は最大 1.1×10⁻¹³（値は 10³ まで） | 同じ | 同じ | 違う（表 2） |
| D | ARM64、既定（FMA を使う） | 同じ | cbrt だけ 20 % の点が違う、最大 4 ULP | C と同じ | 同じ | 同じ | 違う（表 2）。**C とは 1 ビットも違わない** |
| E | ARM64、`-ffp-contract=off` | 同じ | cbrt だけ（D と同じ） | 同じ | 同じ | 同じ | 同じ |
| F | x86、`-O3 -march=native -ffast-math` | 同じ | 8 つの関数すべて、23〜68 % の点が 1〜3 ULP | C と同じ | 34 ULP（相対 6×10⁻¹⁵） | 56 % の点が違う。差は最大 4×10⁻¹⁶（値は 1 まで）。反復の数は同じ 5,219 | 違う |

読み方：

- A・E：FMA を止めれば、x86 と ARM64 は cbrt を除いてすべて同じ。**CPU の演算に違いは無い。**
- C と D が同じ：ARM64 の既定と、x86 で FMA を使った場合は、cbrt を除いて 1 ビットも違わない。**違いを作っているのは CPU の種類ではなく、FMA を使うかどうか。**
- 収束する反復：F を除いて全点が同じ。ただしこのラプラス方程式の反復は 0.25 倍（丸めの出ない掛け算）と足し算だけで、FMA の効く式が無い。OpenFOAM の計算では同じにならなかった（3.3 節）。

### 3.3 OpenFOAM の計算（pitzDaily、simpleFoam、k-ε、12,225 セル）

OpenFOAM v1912（Ubuntu 24.04 のパッケージ 1912.200626）の x86 版と ARM64 版で、チュートリアルの pitzDaily を走らせた。変えたのは出力の桁（`writePrecision 16`）と、流線の出力を外したことだけ。ARM64 版は QEMU 8.2 で走らせた。比べたのはセルの値どうしで、`foamdiff.py` を使った。

表 5　差が生まれる所（圧力の式の初めの残差と、線形ソルバー GAMG の反復の数）

| 反復 | 残差の相対の差（x86 と ARM64） | GAMG の反復の数（x86 / ARM64） |
|---|---|---|
| 1 | 0（表示の 16 桁まで同じ。終わりの残差は 13 桁目から違う） | 17 / 17 |
| 2 | 0.7 % | 14 / 15 |
| 5 | 2.8 % | 3 / 3 |
| 50 | 0.2 % | 4 / 4 |
| 280 | 1.6 % | 5 / 5 |

読み方：1 回目の反復の終わりで 10⁻¹³ の程度だった違いが、2 回目で GAMG の反復を 1 回ずらし、差は一気に 10⁻² の程度になる。線形ソルバーは「残差が 0.1 倍になったら止める」ので、止まる回が 1 回ずれると、解はその判定の大きさだけ変わる。その後は SIMPLE の反復が進むにつれて、差は反復の誤差とともに縮む。

## 4. 実機での測り方

### 4.0 報告書のケースを 2 台で比べる（いちばん大事な手順）

道具：`run_machine.sh`（各計算機で走らせて結果を 1 つの tar.gz にまとめる）、`compare_machines.py`（2 つの tar.gz を比べる）。どちらもこの調べで試した（同じ計算機で同じ条件を 2 回走らせると全セルが 1 ビットも違わない、x86 と ARM64 の 1 並列どうしは 3.3 節の表 4 の 100 反復と同じ値になる、を確かめた）。

**選ぶケース**：リーズの西風・対策なし（約 120 万セル、simpleFoam、報告書では 2,000 反復で判定を満たして停止）。メッシュを作ったあとのケースのフォルダ（`constant/polyMesh` がある）を 2 台に同じものとして置く。

**見立て**（結果を見る前に書く）：500 反復で、2 台の速度の差は最大の値の 1 % 以下、領域の平均の風速比の差は 0.01 以下。並列数を 4 と 8 で変えた差は、2 台の差と同じ程度か大きい。

**手順**

1. 各計算機で OpenFOAM の環境を読み込み（Docker ならコンテナの中で）、作業用の空のフォルダに移って走らせる。2 台で同じ反復の数・同じ並列数にする。

```bash
bash run_machine.sh ケースのフォルダ 500 4
```

2. できた `fp_計算機の名前_ケース_n4_i500.tar.gz` を 1 か所に集めて比べる。

```bash
python3 compare_machines.py fp_i7_*.tar.gz fp_m6_*.tar.gz U p k
```

3. 並列数の効きと比べるため、どちらか 1 台で並列数 8 も走らせ、同じように比べる。

`run_machine.sh` がすること：ケースをコピーし（元のフォルダは書き換えない）、反復の数で止める（`residualControl` を外す）、16 桁の ascii で最後の時刻だけ書く、毎回同じに分かれる `hierarchical` で領域を分ける、計算機・OpenFOAM の版・かかった時間を `machine.txt` に残す。root で動かす Docker では `MPIRUN_ARGS="--allow-run-as-root"` を付ける。


### 4.1 fpcheck（各計算機で 1 分）

各計算機（i7・i9・M5 Max・M6）で次を実行し、できた `.txt` と `.bin` を 1 か所に集める。

```bash
cc -O2 -o fpcheck fpcheck.c -lm
```

```bash
./fpcheck "$(hostname).bin" > "$(hostname).txt"
```

集めた所で 2 台ずつ比べる。

```bash
python3 compare.py i7.bin m6.bin
```

`.txt` の先頭に、その計算機のコンパイラ、FMA にまとめたか、long double のビット数が出る。OpenFOAM を Docker の中で走らせている計算機では、fpcheck も同じ Docker の中で作って走らせる（数学関数のライブラリが macOS のものと違うため）。

### 4.2 OpenFOAM の計算（報告書に載せるならこちらが要る）

fpcheck は小さな式の違いを見るもので、報告書の量（風速比、流量、温度）がどれだけ違うかは OpenFOAM の同じケースを各計算機で走らせて比べる。そろえるもの：

1. OpenFOAM の版と作り方（同じ版。Docker なら同じイメージの x86 版と ARM64 版）
2. 並列数と領域の分け方（まず 1 並列。次に同じ並列数・同じ `decomposeParDict`。`scotch` は版で分け方が変わるので `simple` か `hierarchical`）
3. 出力の桁（`writePrecision 16` か `writeFormat binary`）
4. 反復の数（判定で止めず、同じ反復の数で止める）

選ぶケース：(a) 判定を満たして停止した定常の計算 1 本、(b) 極限周期か打ち切りの計算 1 本。(a) で報告する量の差が反復の誤差より小さいこと、(b) で差が位相による振れの幅に入ることを見る。結果を見る前に、見立てを書いておく（3.3 節の値からは、(a) は報告する量で 0.1 % 以下）。

場の比べ方（同じ時刻の U と p）：

```bash
python3 foamdiff.py ケースA ケースB 280 U p
```

## 5. まだ確かめていないこと

- 4 台の実機での測定（この文書の数値はクラウドの x86 とエミュレーター）
- Apple の libm（macOS でじかに作った場合）と glibc の違いの大きさ
- 報告書のケース・版（v2606）での違いの大きさ（3.3 節はチュートリアルの 1 ケース、v1912）
- 非定常・極限周期の OpenFOAM の計算での違い
- 使っている OpenFOAM がどのコンパイラ・どの設定で作られているか（FMA にまとめているか）
- M6 の仕様（ARM64 であることを前提にした）
